# Walkthrough (Журнал змін)

## [v0.18.0] - 2026-08-08
- **Пряме підтягування невідправлених чернеток з сервера Нової Пошти**:
  - У `NovaPoshtaClient` (`src/nova_poshta/client.py`) додано метод `get_internet_document_list()`, що звертається до ендпоінта `InternetDocument/getInternetDocumentList`.
  - У `cmd_drafts` (`/drafts` / `📝 Мої чернетки (ТТН)`) реалізовано об'єднання створених через бота чернеток та створених/редагованих безпосередньо на сайті Нової Пошти.
  - Оновлено вирахування статусу `is_shipped` у `get_documents_status`: чернетки зі статус-кодами 1, 2, 3 (електронні ТТН до передачі у відділення) більше не видаляються з пам'яті.
- **Зручний вибір способу виплати накладеного платежу (Готівка / Картка)**:
  - У клавіатуру перевірки ТТН (`src/bot/keyboards.py`) додано інтерактивну кнопку `🔄 💳 Виплата: На картку (4149...1234)` / `🔄 💵 Виплата: Готівкою у відділенні`.
  - Реалізовано перевірку наявності картки: якщо користувач обирає виплату на картку, а картку ще не збережено, бот виводить дружній покажчик для збереження картки (`/set_card`).
  - Додано автоматичне виявлення 16-значного номера картки у текстових повідомленнях чату з авто-збереженням у профілі.
- **Тестування**: усі 24 модульні тести виконано успішно (`24 passed`).

## [v0.17.1] - 2026-08-08
- **Автоматична вимога `declared_value >= cod_amount` (Оцінка товару >= Наложки)**:
  - У `src/bot/handlers.py` та `src/nova_poshta/client.py` додано автоматичну синхронізацію оціночної вартості з сумою накладеного платежу:
    - При парсингу ШІ або первинній обробці: `declared_value = max(declared_value, cod_amount)`.
    - При зміні наложки кнопкою `cycle_cod`: якщо наложка перевищує поточну оцінку, оцінка автоматично підтягується до суми наложки.
    - При зміні оцінки кнопкою `cycle_value`: оцінка не може опуститися нижче за суму наявного накладеного платежу.
- **Тестування**: усі 24 модульні тести виконано успішно (`24 passed`).

## [v0.17.0] - 2026-08-08
- **Точний штрихкод реєстру (ScanSheet)**:
  - У `generate_code128_barcode` (`src/utils/barcode_gen.py`) прибрано видалення дефісів. Текст реєстру кодується у форматі Code128 з точним збереженням дефісів (наприклад, `105-79184007`). Згенерований у Telegram штрихкод відтепер 100% сканується сканерами Нової Пошти.
- **Підтримка Накладеного платежу (COD / Грошовий переказ)**:
  - **AI Extractor (`src/ai/extractor.py`, `src/ai/schemas.py`)**: додано розпізнавання суми накладеного платежу (`cod_amount`) та типу виплати (`cod_payment_type`: готівка/картка) з текстів користувача (наприклад, *"наложка 1500 грн"*).
  - **Nova Poshta API Client (`src/nova_poshta/client.py`)**: додано підтримку масиву зворотної доставки `BackwardDeliveryData` при використанні `cod_amount > 0` та метод `get_payment_cards` для отримання банківських карт відправника.
  - **Інтерфейс бота (`src/bot/handlers.py`, `src/bot/keyboards.py`)**: додано інноваційну кнопку `🔄 💰 Наложка: 1500 грн` у картку перевірки ТТН (циклічний вибір суми: 0, 500, 1000, 1500, 2000, 3000 грн) та команду `/set_card` для збереження банківської картки за замовчуванням.
- **Тестування**: оновлено `tests/test_scan_sheet.py` для перевірки збереження дефісів у Code128. Усі 24 тести виконано успішно (`24 passed`).
